# c04 上的控制组迁移与组合设计

2026-10-07：用户明确授权恢复 zxVAD 并进行组合优化。旧十轮的主方案、控制组及审核结论保持原样；本批给控制组另设新候选身份。

控制组变成候选的条件是：它确实改变了功能、有可解释假设、固定配方，并在新 baseline 上有自己的单项实验。旧控制组胜出不能证明旧主方案的复杂机制成立，也不能直接宣称新改进成立。

| 历史身份 | 历史 macro AUROC (%) | 与旧 baseline 的差值 (pp) | 本次处理 |
|---|---:|---:|---|
| NGW constant 控制 | 82.9124 | +2.5854 | 晋升为 N：减弱 G 接受的正常性指导强度；不再声称“预热”机制 |
| MQD compact 控制 | 82.7462 | +2.4192 | 晋升为 Q：只做正常查询紧致约束，排除分离性项 |
| TCA coherent 主方案 | 82.6719 | +2.3449 | 保留为 T：片段共享外观变化，高于 framewise 控制 |
| BFP uniform 控制 | 82.6640 | +2.3370 | 可作为后续软混合候选；本批不同时改伪异常生成 |

历史 baseline 为80.3270%，同一 seed17。历史数据只用于选择本批开发方向，不能与新 baseline 做直接差值；V2 的网络、正常性训练路径和 Avenue 标签发生过变化。

本批唯一 baseline 是已审核 `3eb129ec5362ebd0575f9531d6ab178f4149e879` 的 c04：hidden-normalized attention + dot memory。它在5090上的结果为77.1323/91.5531/84.5319%，但本批重新训练 B，所有增益都相对这次3090上的 B。作者实现细节仍未确认，c04 是经目标反馈选择的开发实现。

三个不足假设与固定实现：

1. **T，外观覆盖不足。** 正常训练片段中共享 RGB affine，概率0.5，gain∈[0.8,1.2]、RGB[0,1]offset∈[-0.1,0.1]，输出裁剪至[-1,1]。同一接收片段的五帧以及其独立正常 donor 使用相同系数。后者是迁移到 c04 的明确实现选择；旧十轮使用片段内 donor，不能称为原封不动迁移。该假设参考 [CVRL](https://arxiv.org/abs/2008.03800) 的时间一致增强原则，不声称复制其完整训练目标。
2. **N，正常性指导强度过大。** 固定 multiplier0.9001。c04 的 `L_G` 中 guidance 系数从0.5变为0.45005；guidance 内部自身包含0.5 MSE。N 的训练损失、调用数、BN 路径和伪异常全部不变。历史 constant 是同预算的强度控制；更高分支持检验“强度”而不能支持“预热”。
3. **Q，正常查询缺少显式紧致约束。** 加0.1×归一化查询到 detached 最近归一化记忆槽的 MSE，最近槽按 cosine/argmax 选择，平分时取最小索引。额外项只直接更新编码器，不直接更新记忆槽或解码器；原 memory forward/shrink/read 保持不变。不加入 triplet separation。参考 [MNAD 官方代码](https://github.com/cvlab-yonsei/MNAD) 的 query compactness 思路。V2 的零熵日志本身不证明记忆塌缩，也不构成本次改动的因果证据。

采用完整2×2×2设计，能区分“单项迁移失败”“相加”“相互抑制”。主对比即使为负也报告，不能事后用胜出的单项替换主对比。报告全部24行目标 AUROC、三目标等权 macro AUROC 和同尺度的组合交互差值；这些差值不等于统计显著性。bootstrap 不作为性能判据，不常规展示区间。

每臂从相同初始化、相同正常源片段/donor计划训练，seed17、batch8、5000step，共40000次参数更新。5000step继承固定 c04 的实现预算，是本研究的配对开发协议，不代表已确认的作者采样方式，也不是覆盖整个训练集的完整 epoch。全部八臂训练后才一次性冻结并评估 final5000，拒绝选择目标分数更好的中间 checkpoint。

数据保持 strict source-only training。源是330个 ShanghaiTech 正常训练视频，共274515帧；目标为Ped1/Ped2/Avenue，固定7056/1962/15240个计分帧。目标标签和视频顺序来自已审核 c04 NPZ，仅构建标签视图；未计分的首四帧使用未知标记−1，不编造标签。3090原始图像字节与5090未被证明完全相同；全部臂共享这次服务器的数据视图和环境。

c04 的随机冻结 ResNet50 O 曾出现接近全图的掩膜。本批原样保留，避免同时混入 O 修改。推理仍只使用 G、负 PSNR、每视频 minmax 和 pooled frame AUROC，禁止目标期增强、N 融合、光流或重新挑选分数规则。

运行环境是独立 venv：torch2.7.1+cu128/torchvision0.22.1 与V2包版本对齐，安装指令核对自 [PyTorch 官方历史版本页](https://pytorch.org/get-started/previous-versions/)。本地 CPU 用2.4.1检查工程语义，服务器必须另过真实 GPU forward/backward、c04直接函数与B wrapper逐位一致性及八臂 source-only更新检查。Python版本和 GPU不同，因此保留新的配对B而不承诺跨服务器逐位相同。

每250step原子保存完整模型、Adam及RNG，可原目录恢复。GPU1有进程时只观察等待，不终止其他实验。完成后手动上传至公开独立复现仓库的新分支；保留原始分数、方案、代码、环境、源抽样计划、训练日志及freeze身份，不上传图像、checkpoint字节或凭据。

若组合胜出，下一批才能预先冻结胜出配方并做新seed配对确认；本批不自动扩大搜索或根据目标结果修改训练。单seed和已多轮查询的目标数据只能支持开发性结论，不能据此直接宣布泛化突破。
